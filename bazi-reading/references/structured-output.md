# 结构化输出

当需要让模型为网页或 API 返回内容时，要求只输出 JSON 对象，不输出 Markdown 或前言。

```json
{
  "overview": "不超过 3 句的总览",
  "sections": [
    {
      "type": "prose | features | timeline | cards | milestones | quote",
      "title": "主标题",
      "kicker": "可选副标题",
      "intro": "可选导语",
      "body": "可选正文",
      "items": [
        {
          "label": "可选标签",
          "title": "小标题",
          "body": "2-4 句，含判断、风险与建议",
          "meta": "仅时间线或年份使用",
          "bullets": ["可选要点"]
        }
      ]
    }
  ]
}
```

推荐类型：

- `features`：命局特征、十神白话、五行补偏。
- `timeline`：大运阶段；`meta` 写年龄或年份。
- `cards`：一生运势、流年分项。
- `milestones`：关键年份；`meta` 写年份。
- `quote`：最后简短总结，不要宿命化诗句。

限制普通模块每项 2-4 句，一生运势八个项目每项 4-6 句。展示端应验证 JSON、删去未知字段、截断超长文本；如果模型输出被截断或 JSON 格式不完整，要求它用更短内容重试一次。

一生运势的“事业”卡片必须同时包含工作形态判断、3-6 个岗位或行业方向、适合与不适合的工作环境。用户提供现实事业状态时，在该卡片中说明当前路径与建议的匹配程度和调整动作。

“财富、健康、夫妻感情、子女、父母、贵人、学业”卡片必须分别落到收入与守财、生活节奏、相处模式、教育边界、现实照护、贵人渠道、学习成果等具体维度；每项都要提供可执行的建议。
